## 2. Did the data model change?

**One field added: `venueBn`.** Everything else reuses existing fields. The
cards derive from `examWindow[0]` (seat and selected notices) and
`sittings[].time` (viva notices).

`venueBn` exists because 87/2026 names its venue in both languages while
85/2026 names it only in Bengali. The view prefers `venueBn` in Bengali and
falls back to `venue`, so 85/2026 renders exactly as before.

### 2a. Selected cards (87/2026)

A preliminary-test result that calls people to a written exam **is** a notice
about an upcoming exam, but its schedule was trapped in hand-written prose
rows — `Be there by: 2:00 PM — the gate closes at 3:00 PM` as one flat string.
Those four rows (`Date`, `Time`, `Venue`, `Be there by`) moved into the
structured fields, so the card now renders the same centre panel, schedule
grid and deadline cards as a seat plan. `Bring` and `Not allowed` stay as
detail rows. **No value changed** — the dates, times and venue are the ones
already hand-verified against the scan on 2026-11-11; only their shape did.

Two knock-on effects, both improvements: the notice now carries a real
`examDate`, so its badge reads **Upcoming** instead of **Open**, and the
notice list shows `Exam 20 November 2026`.

A **parser bug was fixed**, which changed two existing values:

```
notices[8].examWindow[1]   "12:25 PM" -> "4:00 PM"     (bscs_348)
notices[12].examWindow     ["1:00 AM","12:25 AM"] -> null   (bb_38)
```

`TIME_RE` was `(?<!\d)(\d{1,2})[.:](\d{2})(?!\d)`, which matched **marks** as
clock times — `প্রতিটি প্রশ্নের মান 1.00 নম্বর` and `0.25 নম্বর কর্তন`. Notice
38/2026 contains no exam time at all and was reporting a 1:00 AM exam. Harmless
while nothing consumed it; fatal once a gate time is derived from it.

The fix requires BB's own unit word after the digits — `টা` (`Uv`) or `ঘটিকা`
(`NwUKv`). Verified by dumping every `d.dd` match in all 13 PDFs: **every real
time carries the unit, no marks figure does.** A flatten-diff of the full
rebuild shows exactly those 2 fields changed and nothing else.

## 3. How arrival and gate times are sourced

**Derived, uniformly, from the exam start — per your ruling.** The brief
forbade inferring gate-closing from the exam start; you overrode that:

> *"uniform for all cases, if the exam starts at 3 so gate will be closed at 3.
> if it 10 then gate closes at ten. no need for notice mention. it should auto
> detect the gate closing time. and on arrival time should be 1hr prior."*

```
gateClose = examStart
arriveBy  = examStart − 60 min
```

This is not a blind guess — it matches the corpus. Decoding the Bijoy-encoded
PDF text gives:

| Notice | Window | "at least 1 hr before" printed | Explicit gate clock |
|---|---|---|---|
| 86/2026 (seat) | 10:00–11:00 AM | yes | **yes — "সকাল ১০.০০টায় … মূল ফটক বন্ধ হবে"** |
| 357/2026 (seat) | 3:00–4:00 PM | yes | no |
| 356/2026 | 2:30–4:30 PM | yes | no |
| 81/2026 | 10:00–11:00 AM | yes | no |

The one notice that prints a gate time prints **the exam start time**, and the
one-hour rule is printed in four notices. The derivation reproduces the source
wherever the source speaks.

Previously `results.js` already rendered `clock(minus60(examWindow[0]))` into a
"Be there by" cell — the same arithmetic, but buried in the view with no label
explaining it. That derivation now lives in one function feeding both cards.

## 4. Missing or ambiguous times

- `examWindow === null` → **`timingsBlock()` returns `""`**. No heading, no
  empty card, no "—". The four selected notices with no stated schedule show
  nothing at all, so absence never reads as "there is no deadline".
- The selected card's centre panel and schedule grid are omitted the same way,
  per field: no venue means no panel, no date means no date cell.
- A window whose end is not after its start is treated as unparsed and becomes
  `null` at build time rather than rendering a wrong start.
- Nothing is rounded, assumed or back-filled. A notice with no printed time
  produces no card.

## 5. EN / BN labels

| Key | EN | BN |
|---|---|---|
| `examSchedule` | Examination schedule | পরীক্ষার সময়সূচি |
| `importantTimings` | Entry deadlines | কেন্দ্রে ঢোকার সময় |
| `arriveBy` | Arrive by | কেন্দ্রে পৌঁছানোর শেষ সময় |
| `arriveHint` | At least 1 hour before the exam starts | পরীক্ষা শুরুর ১ ঘণ্টা আগে |
| `gatesClose` | Gates close | গেট বন্ধ হবে |
| `noEntryAfter` | No entry after this time | এরপর কেন্দ্রে প্রবেশ করা যাবে না |

The brief's `গুরুত্বপূর্ণ সময়সূচি` was dropped: with the new heading in place a
viva card read `আপনার সময়সূচি` → `পরীক্ষার সময়সূচি` → `গুরুত্বপূর্ণ সময়সূচি`, three
headings ending in the same word. `কেন্দ্রে ঢোকার সময়` is concrete and says what
the two cards actually are; `yourSitting` became `আপনার ভাইভা`.

**Removed as duplication** — the arrival card now prints the real clock time,
so the generic step saying the same thing less precisely was dropped from both
instruction lists (EN *"Reach the centre at least one hour early."* / BN
*"পরীক্ষা শুরুর অন্তত এক ঘণ্টা আগে কেন্দ্রে পৌঁছান।"*, and the viva equivalent).

**Two other time bugs fixed:**
- The viva cell labelled **"Reporting time"** was showing the **sitting start
  time** — it told a candidate to turn up at the moment they should already be
  seated. Relabelled to `time`; the real arrival time is now the green card.
- `clock()` mapped 15:00 to **দুপুর**. BB writes `দুপুর ২.৩০টা` but `বিকাল ৩.০০টা`,
  and brief §5 agrees, so the boundary moved to 15:00. 3 PM now reads `বিকেল ৩টা`.
  (Brief §3's example said `দুপুর ৩টা` — it contradicts its own §5; the source wins.)

## 6. Accessibility and layout

- Colour is never the only signal: each card carries an inline SVG icon **and**
  a text label. Asserted in uitest.
- Time is the most prominent element — `clamp(20px,2.8vw,25px)`, 600 weight,
  above the hint line.
- `font-variant-numeric: tabular-nums` on both times. Asserted in uitest.
- Schedule content stays outside the live region — `#result` has no `aria-live`
  (announcements go through `#srstatus`). Asserted in uitest.
- `minmax(215px,1fr)` drops the pair to one column before either time can be
  squeezed. No horizontal scroll at 360 px (asserted).
- Print: colour dropped, `1px` border on arrival and `2px` on gate so the two
  stay distinguishable in grayscale. Roll 221034 still prints 2 pages.

## 7. English default and `Job ID`

- **`Job ID` is English in both locales** — unchanged. The BN dictionary
  deliberately has no `job` key; the parity test requires the EN/BN key
  difference to be exactly `{"job"}`.
- **English is _not_ the unconditional first-visit default, by your ruling.**
  A browser reporting `bn-*` opens in Bengali on first visit; every other
  browser opens in English; a saved preference always wins. You confirmed this
  (`keep_sniff`) against the brief's §2/§9/§10. Stating it plainly here rather
  than claiming a default the build does not have.
